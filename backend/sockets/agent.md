# Rules
- `sockets/` is the real-time counterpart to `api/` — it's how the server pushes live state to the browser (a document finished extracting, tags were applied, a field was verified) so the client doesn't have to poll. If data only needs to be fetched once or on-demand, that's a REST route in `api/`, not a socket event.
- `middleware/` holds Socket.IO middleware, run in `io.use()` order at connection time (files load sorted by name). One file per concern, named for what it does (`socketPresence.ts`), default-exporting `(socket, next) => void`. There is no auth middleware — auth was cut for the demo, so every connection is anonymous.
- `events/` holds client → server event handlers. Folder structure IS the event name, same convention as `api/` (`api/agent.md`): a file's path relative to `events/`, extension stripped, joined with `:` is the event it registers for — `events/households/watch.ts` → `households:watch`. Don't hand-write event name strings elsewhere.
- One file = one event. Default export is `{ config, handler }` (`SocketEventModule`) — the event name comes from the path, never a field. Nothing else lives at the top level besides the payload schema and any local types it needs.
- Event files are thin: validate the payload, call a service, shape the ack. No DB/queue logic in `events/` — that belongs in `services/` (or `mq/`), same split as `api/` + `services/`.

# Specifics
- `config: SocketEventConfig` declares `rateLimitPoints` — `socketLoader` (the "setup loader" per `loaders/agent.md`) enforces it before `handler` runs, rejecting with a failed ack instead of calling the handler. Don't reimplement it inside a handler.
- `handler` is typed `SocketEventHandler` and receives `(payload, { socket })`.
- `handler` returns its ack body as a plain object (`{ success, ... }`); it never calls `socket.emit` as the response to its own event — that's what the ack is for. Only reach for `ctx.socket.emit(...)` directly for an out-of-band message alongside the ack, or from `services/` for server-initiated broadcasts (below).
- Validate the payload with a local zod schema (`payloadSchema`, same `*Zod` convention as `api/agent.md`) at the top of the handler; on a domain failure, throw `AppError(message, statusCode, code)` rather than returning a failed ack manually — `socketLoader`'s dispatch catches it and formats the ack, same convention as `api/agent.md`/`services/agent.md`/`mq/agent.md`.
- Server-initiated broadcasts (a document's extraction finished, a household's tags changed) are not event files — they're a call to `realtimeNotifyRooms(rooms, event, payload)` or `realtimeNotifyAll(event, payload)` from `services/realtime/realtimeMethods.ts`, made by the owning service after its state change commits. That service is the only place that touches the `io` singleton `socketLoader` exports; nothing else calls `io.emit` directly. It never throws — a broadcast is best-effort and must not fail the job or request that caused it. `events/` only holds handlers for messages the client sends first.
- Rooms are named with `socketRoom(kind, id)` from `modules/socketRoom.ts` (`household:{householdId}`, `document:{documentId}`). A client joins a room by sending an event (`households:watch`) whose handler calls `ctx.socket.join(socketRoom(...))`. Services target rooms through `realtimeNotifyRooms`, never by building room strings themselves.
- **Every server → client event is one shared file that declares itself** — there is no list of event names or type map to keep in sync. `shared/src/types/native/sockets/<event path>.ts` default-exports `defineSocketEvent<Payload>()("<event name>")`, with the path mirroring the name (`documents/extracted.ts` → `documents:extracted`), same rule as API routes. Both sides import that object and pass it — `realtimeNotifyRooms(rooms, event, payload)`, `useSocketEvent(event, handler)` — so the payload type comes from the event itself and an event name string is never typed anywhere else.
- Events are **signals, not data**: a broadcast says what changed (`{ documentId }`) and the client refetches its REST queries, which stay the source of truth. Push actual values only for high-frequency or many-viewer updates (live progress), and then send the absolute value, never a delta, so a missed message corrects itself on the next one.
- If a socket needs the shared Redis client for anything (adapter, presence counts), it comes from `redisLoader`'s export (per `loaders/agent.md`) — `socketLoader` may `.duplicate()` it for the pub/sub adapter, but nothing in `sockets/` opens a second standalone connection.
- Every server instance syncs through the Redis adapter, so an emit from any instance or queue worker reaches a socket connected anywhere. Connections are WebSocket-only, which is what lets multiple instances run without sticky sessions — don't re-enable the polling transport.
- `socketLoader` is both loader shapes at once: it creates the `io` singleton at import (so services can import it, like a resource loader) and `loadSockets(server, allowedOrigins)` attaches it to the HTTP server, `middleware/` and `events/` during boot (like a setup loader).
- `SocketEventHandler`, `SocketEventConfig`, `SocketEventModule` and the `AppSocket`/`AppServer` shapes are shared infrastructure used by every event file — they live in `types/native/sockets` (per `types/agent.md`), not redefined per file, same treatment as `JobHandler` in `mq/agent.md`.
- If a payload or ack shape needs to be shared with the frontend (the client emits it, or types its ack callback), define it once in `shared/src/types` per `types/agent.md` and import it here — don't duplicate it as a one-off local schema, same rule as `api/agent.md`.
