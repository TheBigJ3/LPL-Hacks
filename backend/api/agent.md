# Rules
- Folder structure IS the route. Each file's path relative to `api/`, extension stripped, is its route path — the loader walks this tree and registers a route per file. Don't hand-write route strings anywhere.
- Group top-level by version (`v1/`), then by system underneath, e.g. `api/v1/documents/upload.ts` → `POST /v1/documents/upload`.
- One file = one route = one HTTP method. Need both `GET` and `POST` on the same path? That's two files in the same folder (e.g. `list.ts` + `create.ts`), not a switch on `req.method`.
- Route files are thin: validate params, call a service, shape the response. No DB/query logic in `api/` — that belongs in `services/` (or `mq/` for queue work).
- Every route file's default export is `{ config, handler }`. A route file never defines its own param or response shape inline — both are imported from `shared/src/types` (see Specifics), so nothing beyond `config`/`handler` and truly route-local glue lives at the top level of the file.

# Specifics
- `config: RouteConfig` declares `method` and `rateLimitPoints`. The loader attaches the rate limiter automatically from it; don't reimplement rate limiting inside a handler.
- There is no auth in this project (cut for the demo). Every route is public, so set `rateLimitPoints` on anything that does real work — uploads, Textract/Bedrock calls, search — and never trust a client-sent household/advisor id to mean more than "which data to show".
- `handler` is typed `RouteHandler`, and `req.user` is always set: the loader runs `apiMiddleware/currentUser.ts` on every route, which attaches the default advisor from `userGetCurrent()` (`services/users/userMethods.ts`, values from the `DEFAULT_USER_*` env vars). Read the acting user from `req.user`, never from params or the body, so swapping `currentUser` for real auth later changes one file and no routes.
- `GET /v1/user/getUser` returns that user (`{ success, userData }`, shape in `shared/src/types/native/api/v1/user/getUser.ts`).
- A handler returns its response body as a plain object; it does not call `res.json()` itself. The loader wraps it, so only reach for `res` directly when you need to bypass the default 200 (e.g. setting a cookie, streaming).
- Every route's param shape and response shape live in `shared/src/types`, mirroring the route's own path exactly (same "folder structure IS the path" idea as `api/` itself) — `api/v1/documents/upload.ts`'s shapes live at `shared/src/types/zod/api/v1/documents/upload.ts` (`export const ParamsZod`) and `shared/src/types/native/api/v1/documents/upload.ts` (`export type Params = z.infer<typeof ParamsZod>`, plus `export type Response`), per the `native/`+`zod/` convention in `types/agent.md`. The route's own path already disambiguates, so the exports don't need to repeat the route's name. This is unconditional — even a route the frontend doesn't call yet gets its shapes defined here, not locally, since the point is one contract both sides import rather than a backend-only copy that can drift from what the frontend types against.
- Only `Params` gets a zod schema — it's crossing a trust boundary (client input) and needs runtime validation. `Response` is our own backend's output, already guaranteed to match by the type system, so it stays a plain native type with no zod counterpart — don't add one "for symmetry."
- A route file imports `ParamsZod` from shared and validates `req.body`/`req.params`/`req.query` with it at the top of the handler — never a locally defined schema. On failed `safeParse`, throw `AppError(message, statusCode, code)` rather than returning an error shape manually — let the shared error handler format the response.
- The handler's return value is typed against the imported `Response` type — the plain object it returns must conform to that shape, not an ad hoc inline shape, so the response the loader sends is guaranteed to match what the frontend imports and types against.
- Side effects that matter for auditing (an advisor verifying or correcting an extracted field, deleting a document) get logged explicitly in the handler after the mutating service call succeeds — don't bury audit logging inside the service.
